# План: профили игроков, друзья и приглашения (Firebase)

Статус: план, не реализовано. Игра остаётся P2P (PeerJS) — Firebase добавляется только для профилей, друзей и приглашений. Без входа в аккаунт всё работает как сейчас.

## Почему Firebase

- Не нужен свой сервер и его оплата/поддержка: SDK работает прямо из статичной игры на GitHub Pages.
- Бесплатный тариф (Spark) с запасом покрывает такую игру: 50 тыс. чтений Firestore в день, 1 ГБ хранилища фото, авторизация без лимитов.
- Всё нужное в одном месте: **Auth** (вход через Google), **Firestore** (данные), **Storage** (фото аватарок).

## Части системы

| Сервис | Зачем |
|---|---|
| Firebase Auth (Google) | Личность игрока: uid, привязка к Google-аккаунту, сохраняется при смене телефона |
| Cloud Firestore | Профили, дружбы, приглашения, статус онлайн |
| Firebase Storage | Файлы аватарок (фото, сжатые до 128×128) |
| PeerJS (уже есть) | Сама игра — не меняется |

## Модель данных (Firestore)

```
users/{uid}
  name      — отображаемое имя (по умолчанию из Google)
  photo     — URL аватарки (по умолчанию фото Google, можно заменить своим)
  code      — личный код друга, 6 символов, уникальный (например K7M2Q9)
  lastSeen  — серверное время последнего «пульса» (heartbeat раз в 60 сек)
  room      — код комнаты, если игрок сейчас в лобби/игре, иначе null

friendCodes/{code}
  uid       — обратный указатель для поиска игрока по коду

friendships/{uidA_uidB}      // id = два uid, отсортированные и склеенные
  a, b      — uid обоих друзей; документ существует = дружба есть

invites/{autoId}
  to, from  — uid получателя и отправителя
  fromName  — имя отправителя (чтобы не читать лишний документ)
  room      — код комнаты, куда зовут
  ts        — время (протухшие >2 мин игнорируются и удаляются)

rooms/{code}                 // реестр лобби — для «списка всех лобби»
  host      — uid хоста
  hostName  — имя хоста
  players   — сколько за столом (люди + боты)
  capacity  — максимум (5)
  status    — 'open' (набор) | 'playing' (идёт игра)
  round     — номер текущего раунда
  avgScore  — среднее арифметическое очков не вылетевших игроков (обновляется после каждого раунда)
  ts        — время последнего обновления (heartbeat хоста; комнаты старше ~3 мин считаются мёртвыми и не показываются)
```

Онлайн-статус: игрок «онлайн», если `lastSeen` моложе ~2.5 минут. Точная presence через Realtime Database возможна, но heartbeat проще и хватает.

## Правила безопасности (суть)

- `users/{uid}`: читать — любой вошедший; писать — только владелец.
- `friendCodes/{code}`: создать может только владелец uid; читать — вошедшие.
- `friendships/*`: создать/удалить может тот, чей uid входит в пару (a или b).
- `invites/*`: создать — если `from == auth.uid`; читать/удалить — отправитель или получатель.
- `rooms/{code}`: читать — вошедшие; создать/обновить/удалить — только хост комнаты.
- Storage `avatars/{uid}.jpg`: писать — владелец, максимум ~300 КБ, только image/*; читать — все.

Готовый текст правил — в GUIDE_FIREBASE.md.

## Изменения в интерфейсе

1. **Главное меню**: карточка профиля сверху (аватар + имя). Не вошёл — кнопка «Войти через Google». Кнопка «👥 Друзья».
2. **Модалка профиля**: аватар (тап — выбрать фото из галереи, обрезка/сжатие до 128×128 на телефоне до загрузки), поле имени, личный код друга с кнопкой «скопировать», выход из аккаунта.
3. **Экран «Друзья»**: поле «добавить по коду», список друзей: аватар, имя, статус (⚫ офлайн / 🟢 онлайн / 🎮 в комнате ABCD). Кнопки: «Позвать» (если я в лобби), «Зайти к нему» (если друг в комнате), удалить.
4. **Комната**: кнопка «Пригласить друзей» → экран друзей в режиме приглашения.
5. **Баннер приглашения**: пришёл инвайт → сверху плашка «Галина зовёт в комнату TVDN [Играть] [✕]». «Играть» — автоматический вход по коду.
6. **За столом**: вместо эмодзи — фото-аватарки игроков (эмодзи как запасной вариант у ботов и гостей без профиля). Аватар и имя передаются в hello/room-сообщениях P2P.
7. **Экран «Все лобби»**: список открытых комнат — имя и аватар хоста, игроков n/5, статус («набор игроков» или «идёт игра, раунд N»), средний счёт стола. Кнопка «Войти»: в открытое лобби — сразу в комнату; в идущую игру — подключение с ожиданием конца раунда. Обновляется вживую (onSnapshot). Доступен вошедшим в профиль.

## Поздний вход в идущую игру

- Пока идёт партия и мест меньше 5, к комнате можно присоединиться из списка лобби (или по коду).
- Новичок ждёт конца текущего раунда (экран «Ждём конца раунда…», видно счёт стола).
- Со следующего раунда он за столом, и его стартовый счёт равен **среднему арифметическому очков не вылетевших игроков** (округление до целого) — чтобы он не заходил с нулём против всех. Пример: у игроков 40, 70 и 85 → новичок начинает с (40+70+85)/3 ≈ 65.
- В движок добавляется `addPlayer(state, {name, avatar, score})` — разрешён только между раундами; хост применяет его и рассылает обновлённое состояние.
- Хост после каждого раунда обновляет в `rooms/{code}` поля avgScore, round, players.

## Основные сценарии

- **Первый вход**: тап «Войти через Google» → окно Google → создаётся `users/{uid}` (имя и фото из Google) + уникальный `code` (транзакция). На мобильных вместо popup — redirect (надёжнее в PWA на iOS).
- **Добавить друга**: ввёл код K7M2Q9 → ищем `friendCodes/K7M2Q9` → создаём `friendships/...`. Дружба взаимная сразу (кодом делятся добровольно — это и есть согласие).
- **Пригласить в игру**: я в лобби с кодом TVDN → «Позвать» у друга онлайн → документ в `invites`. У друга открыт список инвайтов (onSnapshot) → баннер → «Играть» → авто-вход в комнату, инвайт удаляется.
- **Зайти к другу**: у друга в профиле `room != null` → кнопка «Зайти» без всякого приглашения.

## Риски и ограничения

- Popup-вход Google местами блокируется в мобильных браузерах и PWA — нужен запасной redirect-вход (учтено в плане).
- Из моей песочницы Firebase недоступен — финальная проверка входа/инвайтов будет на реальных устройствах.
- Чужие фото никак не модерируются: аватарку видят только те, кто играет с этим человеком, но стоит помнить.
- index.html потяжелеет примерно на 0.5–0.7 МБ (Firebase SDK) — для мобильного интернета терпимо, кэшируется PWA.
- Профиль на Spark-тарифе бесплатен при любых реалистичных масштабах этой игры; платить пришлось бы только при десятках тысяч активных игроков в день.
